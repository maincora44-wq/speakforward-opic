# SpeakForward 음성 답변 구현 명세

상태: 구현 완료, 자동 테스트 검증. 조사 대상은 사용자의 후속 요청에 따라 스픽으로 변경했다. [REA 결과](REA_EXECUTED_REPORT.md)와 [근거별 흐름](USER_FLOW.md)을 함께 읽는다.

## 목표와 설계

기존 5분 비즈니스 질문 수업에서 듣고, 직접 질문을 말하고, 받아쓴 내용을 확인하고, 피드백 후 재시도할 수 있게 한다. 스픽 공식 도움말의 음성·타이핑 전환을 일반적인 학습 패턴으로 참고했으며 기존 SpeakForward 문항·채점·복습 로직 위에 독립 작성했다. 스픽의 코드·문항·디자인 자산을 앱에 복제하지 않는다.

브라우저의 `SpeechRecognition` 또는 `webkitSpeechRecognition`을 선택적으로 사용한다. 별도 API 키·백엔드·유료 AI 서비스·런타임 패키지를 추가하지 않는다. 이는 브라우저 받아쓰기 기능이며 자유 대화 AI나 발음 채점 기능이 아니다. 기존의 24문항, 네 수업, 규칙 기반 피드백, 10분/1·3·7일 복습과 네 가지 기존 연습 메뉴를 유지한다.

## 입력 상태와 동작

| 상태 | 화면·행동 |
|---|---|
| 기본 | 텍스트·단어 선택 가능. 마이크 자동 요청 없음. |
| 연결 중 | 사용자가 말로 답하기를 누른 뒤에만 인식을 생성·시작한다. 중복 시작 버튼을 잠근다. |
| 듣는 중 | 영어 받아쓰기 결과를 답안 칸에 표시하고 중지 버튼을 제공한다. 자동 제출하지 않는다. |
| 확인·수정 | 인식 종료 후 텍스트를 편집하고 직접 제출할 수 있다. |
| 조용히 입력 | 인식과 음성 재생을 멈추고 답안에 초점을 둔다. 마이크 없이 완료 가능. |
| 권한·연결 오류 | 구체적인 상태 안내를 제공하고 직접 입력·다시 말하기를 사용할 수 있다. |
| 피드백·일시 정지 | 인식을 중지하고 음성 시작을 막는다. |
| 이동·백그라운드 | 인식 중지, 이벤트 연결 해제, generation 검사로 늦은 콜백 폐기. |

음성 인식 시작 전에 예시 음성 재생을 멈춘다. 예시 재생을 시작할 때도 인식을 멈춰 앱의 음성을 받아쓰는 충돌을 줄인다. 인식이 끝났다는 사실로 정답·학습 완료를 처리하지 않는다.

## 데이터·접근성

- 음성 인식 서비스를 브라우저 제공자가 처리할 수 있다는 설명과 마이크 시작 버튼을 함께 제공한다.
- 인식 문장은 답안 칸에서만 사용하며 Question Builder의 localStorage·내보내기에 추가하지 않는다. 직접 작성한 문장·인식 문장 모두 기존 채점기로 처리한다.
- 상태는 `role=status`와 텍스트로 알린다. 음성 시작 버튼의 눌림 상태와 중지 버튼의 활성 상태를 동기화한다.
- API 미지원이나 권한 거부가 수업 완료를 차단하지 않는다.
- 앱 셸 캐시는 `speakforward-shell-v2`로 올려 기존 설치에서 새 버전을 받을 수 있게 한다.

## 검증 기준과 결과

29개 자동 테스트가 통과했다. 그중 새 음성 경로 검증은 다음을 포함한다.

1. 수업 시작 시 인식기를 만들지 않고 사용자 클릭 뒤에만 시작한다.
2. 중간·최종 받아쓰기 결과를 표시하되 직접 제출하기 전까지 피드백을 생성하지 않는다.
3. 제출한 답안은 기존 평가기로 처리하고 받아쓴 원문을 진행 기록에 저장하지 않는다.
4. 권한 거부·네트워크·음성 없음·미지원·시작 예외 후에도 직접 입력 가능하다.
5. 일시 정지·직접 입력·단어 선택·메뉴 이동·백그라운드·페이지 종료·수업 목록에서 인식기를 중지한다.
6. 인식을 중지한 뒤 도착한 콜백이 입력을 덮어쓰지 않는다.
7. 기존 수업 완료·복습·이어하기·네 가지 기존 메뉴·패키지 검증이 계속 통과한다.

DOM 테스트는 모의 음성 인식기를 사용한다. 실제 Android 마이크·TTS·설치·서비스 워커 교체·비행기 모드·TalkBack·렌더링은 별도 기기 확인이 필요하며 통과로 기록하지 않았다.
